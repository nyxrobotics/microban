# MSI FORCE GC300 WIRELESSでロボットを単独操縦する

GC300をロボットのRaspberry PiにBluetooth接続します。操縦中にPCやPICOは不要です。
ロボットのWi-Fiは有効のままです。古い`microban-gamepad.service`はBluetooth接続時にWi-Fiを
切るため、この構成では使いません。

## 初回のBluetooth接続

GC300の無線モードをBluetoothマークにし、Dragonボタンを長押ししてLEDを青点滅にします。
ロボットへSSH接続して、次を実行します。

```bash
bluetoothctl power on
bluetoothctl pairable on
bluetoothctl --timeout 30 scan on
bluetoothctl pair XX:XX:XX:XX:XX:XX
bluetoothctl trust XX:XX:XX:XX:XX:XX
bluetoothctl connect XX:XX:XX:XX:XX:XX
bluetoothctl info XX:XX:XX:XX:XX:XX
jstest --event /dev/input/js0
```

表示名は`MSI FORCE GC300 WIRELESS`です。上記の`XX:...`はスキャンで表示されたMACアドレスに
置き換えます。接続後の`/dev/input/js*`はロボット側にできます。
この環境での入力は2026-09-27〜28に確認し、
左スティックは軸0/1、右スティックは軸2/3、LTは軸5、Aはボタン0、Yはボタン3、Xはボタン4でした。

## ロボット起動時からGC300を使う

ロボット上のこのリポジトリで、一度だけ次を実行します。

```bash
sudo bash systemd/configure-gc300-runtime.sh install
sudo bash systemd/configure-gc300-runtime.sh enable
```

`enable`はPICOランタイムを停止し、GC300ランタイムを今すぐ起動して次回のロボット起動にも登録します。
GC300をまだ接続していなくてもランタイムは起動し、接続を待ちます。起動直後はトルクOFFです。
GC300を使う間にPCは不要です。歩行・立位にはロボット内の`src/agents/gc300_walk.onnx`
を使います。これはGC300専用の学習済み歩行モデルで、PICO用モデルとは別ファイルです。
学習中のモデルを途中で試す場合は、最新の書き出し済みONNXをこのパスへ配置してから
`microban-gc300-runtime.service`を再起動します。起動時はいったんトルクOFFになります。

現在の試用モデルは`mjlab_microban`の`2026-09-27_18-18-25_centered_home_v4_legacy_walk_15000`
にある`model_14000.pt`と同時に書き出されたONNXです。`gc300_walk.onnx`のSHA-256は
`2050d4e51f789fa67fb0accfd58fc817a3472e4562ae1055a7ad9aa5acd77ef4`です。
学習が進んでもロボット上の試用モデルは自動では切り替わりません。

| GC300操作 | 動作 |
| --- | --- |
| A | トルクON、初期姿勢への移動、ポリシーOFF |
| B | トルクOFF |
| 右スティック押し込み（R3） | 立位・歩行ポリシーON/OFF |
| Y | AでトルクONにした後、人追従を開始。ポリシーOFFなら自動でON |
| X | 人追従を終了。トルクと歩行ポリシーは維持 |
| LTを保持 | ポリシーON中に歩行。離すと立位バランス |
| 左スティック | 前後・左右の速度 |
| 右スティック左右 | 旋回速度 |

Aを押して初期姿勢への移動が終わってから、単独の立位・歩行はR3、
人追従はYで開始します。LTは接続やA操作の後に一度離すと
歩行が有効になります。右トリガーとグリップに相当するPICOの頭・腕追跡機能は使いません。
GC300のAで移動する初期姿勢と、R3でポリシーをOFFにした後の戻り先は、左右の足首ピッチを前傾方向に1度補正します。
ポリシーON中の左右の足首ピッチ目標にも同じ1度を加え、Aからポリシーへの切り替え時に補正量を変えません。
ポリシーへ渡す足首の受信角は、直前の足首目標に加えた補正を逆向きに戻してから使います。
生の受信角や転倒判定などの安全監視値は補正しません。
学習用HOMEと転倒復帰ポリシーの目標値は変更しません。
GC300のSTARTなどは操作に割り当てていません。GC300の通信が途切れても自動で
トルクOFFにはしません。切断後1秒までは前回の操作を継続し、その後は速度目標だけゼロにして
ポリシーの更新を続けます。1秒以上の切断後に再接続した場合は、LTを一度離してから歩行を再開します。

ポリシーON中（R3後）に転倒すると、約0.3秒後に自動で起き上がりを始めます。起き上がって
約0.5秒直立すると、制御は立位バランス（歩行ポリシー、速度0）に戻ります。歩行を再開するには、
起き上がった後にLTを一度離してから押し直してください。LTを握ったままでは歩き出さず、その場で
立ち続けます。起き上がりの途中で離して押し直しても数えられないので、起立後にもう一度離します。
MuJoCo上の実ランタイム（2026-10-02）では、歩行中に押されて転倒した107件すべてが1回で起き上がりました。
押し直しから0.1〜0.4秒で歩行速度の半分に達し、その後は押される前と同じ速度・旋回量で歩きました。

Yの追従は別リポジトリ`microban_person_tracking`の顔検出サービスを使います。顔が見えない・
映像が古い場合は追従の速度指令を0にし、首の向きを最大1秒保持してから約40度上向きにして
顔を探します。カメラは床から約32 cmの高さにあり、正面を向いたままでは近くの人の顔は
画角に入りません。
顔が見えた場合は、画像上の顔幅と見上げ角から床面上の距離を概算し、約0.6 m以下では
前進を止めます。顔幅は12 cmと仮定するため、実際の停止距離は人や顔の向きで変わります。
顔への見上げ角が75度以上でも前進を止めます。首の目標角には別途約69度の上向き上限があります。
ステレオ深度や障害物検出は使っていません。
A/B/R3やLTでの手動操作は通ります。LT中は手動の
速度指令を優先し、Yの追従中だけ首が顔を向きます。A/B、またはR3でポリシーをOFFにすると
追従も解除します。ゲームパッドが1秒以上切れた場合は、再接続後にYを押し直します。
YはポリシーOFF中でも自動でポリシーをONにします。トルクOFF中は先にAを押す必要があり、
AとYが同じ制御周期に入った場合はYを押し直すようログに記録します。

状態の確認:

```bash
sudo bash systemd/configure-gc300-runtime.sh status
journalctl -u microban-gc300-runtime.service -f
bluetoothctl info XX:XX:XX:XX:XX:XX
```

PICO操縦に戻す場合は`sudo bash systemd/configure-gc300-runtime.sh pico`を実行します。
この切替では現在のランタイムを止めて一度トルクOFFにします。PICOのAとR3で再開します。
