# MSI FORCE GC300 WIRELESSでロボットを単独操縦する

GC300をロボットのRaspberry PiにBluetooth接続します。操縦中にPCやPICOは不要です。
ロボットのWi-Fiは有効のままです。古い`microban-gamepad.service`はBluetooth接続時にWi-Fiを
切るため、この構成では使いません。

## 初回のBluetooth接続

GC300の無線モードをBluetoothマークにし、Dragonボタンを長押ししてLEDを青点滅にします。
ロボットへSSH接続して、次を実行します。

```bash
bluetoothctl power on
bluetoothctl pairable on
bluetoothctl --timeout 30 scan on
bluetoothctl pair XX:XX:XX:XX:XX:XX
bluetoothctl trust XX:XX:XX:XX:XX:XX
bluetoothctl connect XX:XX:XX:XX:XX:XX
bluetoothctl info XX:XX:XX:XX:XX:XX
jstest --event /dev/input/js0
```

表示名は`MSI FORCE GC300 WIRELESS`です。上記の`XX:...`はスキャンで表示されたMACアドレスに
置き換えます。接続後の`/dev/input/js*`はロボット側にできます。
この環境での入力は2026-09-27に確認し、
左スティックは軸0/1、右スティックは軸2/3、LTは軸5、Aはボタン0でした。

## ロボット起動時からGC300を使う

ロボット上のこのリポジトリで、一度だけ次を実行します。

```bash
sudo bash systemd/configure-gc300-runtime.sh install
sudo bash systemd/configure-gc300-runtime.sh enable
```

`enable`はPICOランタイムを停止し、GC300ランタイムを今すぐ起動して次回のロボット起動にも登録します。
GC300をまだ接続していなくてもランタイムは起動し、接続を待ちます。起動直後はトルクOFFです。
GC300を使う間にPCは不要です。歩行・立位にはロボット内の`pico_teleop`ポリシーを使い、
位置追跡の入力はなしとして扱います。

| GC300操作 | 動作 |
| --- | --- |
| A | トルクON、初期姿勢への移動、ポリシーOFF |
| B | トルクOFF |
| 右スティック押し込み（R3） | 立位・歩行ポリシーON/OFF |
| LTを保持 | ポリシーON中に歩行。離すと立位バランス |
| 左スティック | 前後・左右の速度 |
| 右スティック左右 | 旋回速度 |

Aを押して初期姿勢への移動が終わってからR3を押します。LTは接続やA操作の後に一度離すと
歩行が有効になります。右トリガーとグリップに相当するPICOの頭・腕追跡機能は使いません。
GC300のX/Y、STARTなども操作に割り当てていません。GC300の通信が途切れても自動で
トルクOFFにはしません。切断後1秒までは前回の操作を継続し、その後は速度目標だけゼロにして
ポリシーの更新を続けます。1秒以上の切断後に再接続した場合は、LTを一度離してから歩行を再開します。

状態の確認:

```bash
sudo bash systemd/configure-gc300-runtime.sh status
journalctl -u microban-gc300-runtime.service -f
bluetoothctl info XX:XX:XX:XX:XX:XX
```

PICO操縦に戻す場合は`sudo bash systemd/configure-gc300-runtime.sh pico`を実行します。
この切替では現在のランタイムを止めて一度トルクOFFにします。PICOのAとR3で再開します。
