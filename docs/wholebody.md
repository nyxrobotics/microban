# 全身トラッキング（PC のお手本を実機で追う）

PC が PICO の体の追跡から写したお手本のフレーム（50 Hz、UDP 5556）を、全身の方策で追う。
方策は学習リポジトリ（mjlab_microban `wholebody-tracking`）の契約 `microban-wholebody-1`。
腕も方策が動かす（18 関節、目標 = HOME + 行動）。

| 部分 | ファイル |
|---|---|
| 契約の照合、自己テスト | `src/wholebody_contract.py` |
| お手本の受信と復号 | `src/input/wholebody_reference.py`（形式は mjlab_microban `docs/wholebody_reference_stream.md`） |
| 観測の組み立て、止める処理 | `src/moves/wholebody.py`（`WholebodyMove`） |
| 方策の切り替え | `src/moves/policy_selector.py`（`PolicySelectableWalkMove` の子） |
| 導入 | `tools/install_wholebody_policy.py` |
| 録画を UDP で流す送り手（試験用） | `tools/wholebody_reference_sender.py` |

## 導入

```bash
PYTHONPATH=src uv run --locked python tools/install_wholebody_policy.py <wholebody.onnx> --source "<学習の commit と run>"
```

契約（HOME、観測の並び、時刻と向きの取り決め、首の扱い）を照合し、自己テスト（学習時の観測の履歴を ONNX Runtime に通し、学習時の出力と一致すること）を通してから、
`src/agents/wholebody.onnx` と `src/agents/wholebody_manifest.json` を書く。歩行・起き上がり・IK トラッキングのファイルと manifest には触れない。
起動時にも同じ照合と自己テストを行い、通らなければ全身トラッキングを使わない（ほかの動作はそのまま動く）。

学習途中の保存点を試運転用に書き出したもの（`dry_run_not_deployable`）は、`MICROBAN_ALLOW_DRYRUN_POLICY=1` のときだけ導入・起動できる。
`make teleop-run ALLOW_DRYRUN_POLICY=1`、`make teleop-sim ALLOW_DRYRUN_POLICY=1` で渡る。

## 動かし方

- 実機は今までどおり `MICROBAN_INPUT=network`（`make teleop-run` か常駐サービス）。お手本の受信は UDP 5556（`MICROBAN_WHOLEBODY_PORT`）で、操縦の包み（5555）と同じ送り手（`MICROBAN_NETWORK_ALLOWED_IP`、`MICROBAN_NETWORK_ALLOWED_IP_FILE`）からだけ受ける。
- 操縦の包みは今の PICO のブリッジのまま（A でトルク、R3 で方策、B でトルク OFF）。`locomotion_policy` は `pico_teleop` のままでよい（`wholebody` も受け付ける）。
- **全身の方策が入っていれば、R3 を入れている間はずっと全身の方策がロボットを動かす**。IK トラッキングの方策で立たせない（v13g2 は立っているだけで震え、実機で倒れた）。
  IK トラッキングの方策を使うのは、全身の方策がない（読めない、自己テストに落ちた）ときと、推論が失敗したとき（次に R3 を入れるか起き上がりから戻るまで）だけ。
  IK トラッキングの操作（PICO のトリガーとスティックの歩行と、右トリガーの腕の操作 `pico_arms`）は使わない（腕は全身の方策が動かす）。
- 全身の動作は、PC の追従が始まるまでの間、止めたあと、お手本の流れが切れたとき、**自分で作るお手本で立つ**。

  | 段階 | お手本 | 次へ |
  |---|---|---|
  | 入り | 測った 21 関節と IMU の姿勢（速度 0、高さは HOME）から HOME の立ち姿へ 1.0 秒（smoothstep）。行き先の向きは入りの始めの IMU の向き | 1.0 秒で「立つ」 |
  | 立つ | HOME の 21 関節、HOME の胴の傾きと高さ、速度 0。向きは IMU の向きを 1 刻み 0.02 rad まで追う（HOME から 30° を超えて傾いている間は止める）。角速度は 0 のまま（押されて回っても、お手本も回っているとは見せない） | 合流の条件がそろったら |
  | 合流 | 自分のお手本から PC のお手本（向きを立つお手本の向きに合わせたもの）へ 1.0 秒（smootherstep）。胴の向きの差は回転ベクトルで消していく | 1.0 秒で「追従」 |
  | 追従 | PC のお手本 | 止める理由 |
  | 惰性 | 最後に追ったお手本がその速度のまま進み、0.2 秒で速度 0（PC の Carry と同じ形）。関節は可動範囲で止め、高さは上へ伸ばさない | 「保持」 |
  | 保持 | 惰性の終わりの姿勢で静止 | 止めてから 0.5 秒で「戻し」 |
  | 戻し | HOME の立ち姿へ 1.5 秒（向きは戻しの始めに固定） | 「立つ」 |

  補間はどれも「今 + 0.02 秒」で計算し（学習のお手本は次の刻みの目標）、速度は補間そのものの微分。
- **合流の条件**（「立つ」の間に、すべてそろったとき）。preflight-fixes の開始の条件を、ここ 1 か所にまとめたもの。
  - ロボットと操縦者が、そろって 25 刻み（0.5 秒）続けて止まって立っている。
    - ロボット：胴が HOME の傾きから 12° 以内で、脚のどの関節も 1.0 rad/s 未満。
    - 操縦者（PC のお手本）：胴が鉛直から 30° 以内、HOME の高さから 2 cm 以内、速さ 0.05 m/s 以下、回る速さ 0.3 rad/s 以下で、旗に STALE・HELD・LATE がない。
      学習の評価が区間を始める立ちフレーム（`benchmark.standing_frames` の胴の条件）と同じ。足裏はお手本の胴だけでは見られないので入れていない。
  - PC の開始が新しく、生きている：CALIBRATED と ACTIVE、下の「止める処理」の流れの判定に当たらない、まだ合流していない開始、線の上で `walk` を求められていない。

  待つ間、ロボットの端末に開始ごとに一度「Whole-body tracking: PC start N waits for the robot and the operator to stand still」と、そのときそろっていない条件を出す。
  **操縦者は開始を押したら 0.5 秒ほど立ったまま止まる**。かがむ・膝をつく・動いている操縦者には合流しない（実機のシミュレーションで、胴が立ち姿より 9〜10 cm 低いお手本から始めると 2 回とも倒れた）。
- 合流しても、観測の履歴と前回の行動は作り直さない（立つ・合流・追従はひと続きで、学習の区間の途中と同じ）。
  作り直すのは、R3 を入れたとき、起き上がりから戻ったとき、安全のための保持が明けたとき、姿勢がずれて入り直すとき（履歴の全行を最初のフレームで埋め、前回の行動を 0）。

## 観測（学習と同じ）

118 値 × 履歴 10（古い順、最後が今）。項目と順は `wholebody_contract.OBSERVATION_SCHEMA`。

- お手本：18 関節の角度と角速度、胴の向きをロボットの胴の座標で見た回転行列の 2 列、胴の速度と角速度をロボットの胴の座標で、お手本の胴で見た重力、胴の高さ。
- ロボット：ジャイロ（IMU の軸）、21 関節の角度（HOME からの差）と角速度、前回の生の行動、胴で見た重力。ロボットの胴の向きは IMU の姿勢（yaw 込み）。
- 突き合わせ：`tests/test_wholebody_observation.py`。学習の環境そのもの（mjlab_microban、play、センサーの遅れ 0）で 3 区間 × 150 刻みの状態とお手本と 118 値を記録し（`tools/wholebody_observation_fixture.py`、`tests/fixtures/wholebody_observation.npz`）、
  実機の組み立てで同じ状態から作り直す。お手本は UDP の形式を通し、PC と IMU にそれぞれ別の yaw を与えて 3 組。最大の差 3.5e-7（float32 の丸め）。動作を通した 10 行の履歴も学習と同じ。

## 止める処理

| きっかけ | 判定 |
|---|---|
| PC が止めた | フレームの CALIBRATED か ACTIVE が 0 |
| 届かない | 最後のフレームから 0.1 秒（5 フレーム） |
| 連番の抜け | 刻みの間に 6 フレーム以上失った |
| 遅れ | 届いたフレームの遅れが、直近 10 秒の最小より 0.15 秒以上大きい（PC の送った時刻と Pi の受けた時刻の差。時計は合っていなくてよい） |
| PC の再起動 | 連番が戻り、送った時刻が 0.5 秒以上新しい |
| STALE / HELD | PC が途切れの扱いのお手本を送っている状態が、STALE で 0.25 秒、HELD で 1 秒を超えた（それまではそのお手本を追う） |
| 追従中の新しい開始 | 合流した開始と違う開始（RESTART、ACTIVE の立て直し） |
| 操縦の包みが `walk` | |
| 姿勢のずれ | お手本の胴とロボットの胴で見た重力の z 成分の差が 1.0 を超えた（学習の終了条件 `anchor_ori` と同じ）。止めずに入り直す（下） |

HELD を 1 秒まで追うのは、PC が途切れ（STALE、HELD、LATE）の間と写しの姿勢へ戻る間に、どのフレームも 1 刻みで学習データの 99.9% 点より大きく変えない（跳ばない）ことが前提（mjlab_microban `docs/wholebody_reference_stream.md` の「途切れの扱い」、preflight-fixes から）。
その写しはお手本の形式の版 2 を送る。それより前の写し（版 1）は、HELD が明けた 1 フレームで保った姿勢から今の姿勢へ跳ぶ（膝で最大約 1 rad、胴の向き 17〜38°、高さ 40〜60 mm）ので、受信が版 1 のフレームを捨てる（追従は始まらず、端末に一度 `Whole-body reference refused: unsupported version 1` と出る）。

姿勢のずれのほかは、どれも同じ流れで止める（方策は動かしたまま）：惰性 0.2 秒 → 保持（止めてから 0.5 秒まで）→ 戻し 1.5 秒 → 自分のお手本で立つ。IK トラッキングの方策には渡さない。
止めた開始（activation）には、どう止まっても二度と合流しない。PC が次に開始したとき（ACTIVE を落として立て直す、または RESTART）に合流する。追従中に PC が新しい開始を送ったときも、いったん止めて立ってから、合流の条件で入り直す。

**姿勢がずれたとき**（合流・追従・惰性・保持・戻しのどれでも）は、測った姿勢から「入り」をやり直す（履歴を作り直し、前回の行動を 0、その開始は済み）。
学習はこの線で区間を終え、次の区間をお手本の上から始めるので、それと同じ扱い。離れたお手本で惰性と保持を続けると、戻しの間に倒れた（設計の試作で 3 回とも）。

既存の安全の仕組みは、ほかの動作と同じに効く：転倒（重力の z > -0.5、60° 超が 0.3 秒）で起き上がり、IMU の異常で保持、過電流で停止、B でトルク OFF、R3 OFF で HOME へ。
- 起き上がりのあとは、起き上がりの姿勢から「入り」→「立つ」。倒れる前に追っていた開始には合流しない。
- 安全のための保持（IMU の異常、シリアルの誤り）：ネットワーク入力では保持の間に `walk` が外れるので、全身の動作は 0.8 秒で HOME へ戻して P900 にし、`walk` が戻ったら「入り」から始める（今の IK トラッキングと同じ。IK トラッキングの方策は使わない）。`walk` が外れない入力（キーボード、シミュレーター）では、保持が明けた刻みに測った姿勢から入り直す。
- 胴が 60° を超えて傾いている刻みは、全身の方策は測った姿勢を保ち、転倒の判定に任せる。

ただし、**合流・追従しているお手本の胴そのものが 60° を超えて傾いているときは、それを追うロボットの傾きを転倒に数えない**（深いお辞儀、床に手を伸ばす動き）。
学習の終了条件（`anchor_ori`、重力の z の差 > 1.0）と評価（傾いたお手本に従うロボットは転倒ではない）と同じ考え方。

- 数えないのは、追っているお手本の胴が 60° を超えている間と、60° 未満に戻ってから 0.5 秒（`FALL_LAG_S`。ロボットはお手本より遅れて起き上がる）。
- お辞儀の途中で止めたときは、惰性・保持・戻しの間も数えない（止めた刻みのお手本の胴が 0.10 m 以上）。
  **床に伏せたお手本で止めたときは数える**（止めた刻みのお手本の胴が 0.10 m 未満、`FLOOR_REF_HEIGHT_M`。PICO の録画で、60° 超の胴は床で 0.05〜0.09 m、お辞儀で 0.10〜0.18 m）。止めた次の刻みから転倒の数えが始まり、0.3 秒で起き上がりに渡る。
- 自分のお手本（入り・立つ）では数える。
- その間も、ロボットの胴がお手本の姿勢から外れたら（重力の z の差 > 1.0）転倒として数える。
- 全身の方策の「60° 超で測った姿勢を保つ」も同じ条件にそろえ、数えない間は方策を動かし続ける。

ロボットの胴の高さは測れないので、追従中にお手本と同じ傾きのまま床に倒れていても、お手本が 60° を超えている間は転倒と分からない（お手本が戻るか、床に伏せたお手本で止めると分かる）。0.08〜0.10 m のお手本（膝立ちに近い姿勢）はどちらにも転びうる。

## 首：追従中はお手本の首、それ以外は HMD

合流と追従の間、首の目標はお手本の `joint_pos` の首の 3 欄（head, neck_roll, neck_pitch。PC が操縦者の頭から作る）。
契約の `neck_control: reference_clamped_slewed` のとおり、`neck_limits_rad_json` に収め、`neck_slew_rates_rad_s_json`（2.5 rad/s）で動かす（学習の `ReferenceNeckTarget` と同じ作り方）。
合流のときは測った首の角度から動かし始める。その間、HMD の首の動作（`hmd_head`）は何も書かない（`WholebodyClaim.neck`）。
入り・立つ・止めたあとは、今までの IK トラッキングの方策のときと同じく、`hmd_head` が動いていれば首は HMD に追従する（右トリガーの間。離すとカメラを水平に保つ）。`hmd_head` が動いていなければ、全身の動作が首を自分のお手本（HOME）へ 2.5 rad/s で動かす。
首は方策の行動ではなく、方策は首の角度と速度を観測で見るだけ。追従中に PC の首で動くのと同じ範囲。
転倒として扱う刻み（胴が 60° 超、お手本はそうでない）は、首の目標をそのまま保つ。

シミュレーション（手で作った首の動き：左右 ±0.8、傾き ±0.25、上下 -0.15±0.35 rad、0.25〜0.45 Hz、`tools/wholebody_reference_sender.py --neck-demo`）：
指令はお手本を制限と速度で抑えたものと一致（差の RMS 0.004〜0.010 rad）。保持と HOME への戻しも指令どおり。
ただし学習と同じゲイン P125 では、実際の首は指令から約 0.5 秒遅れ、HOME に戻ったあとも 0.1〜0.14 rad ずれたまま止まる（サーボのモデルの摩擦 0.025 Nm に対し 0.275 Nm/rad、約 0.1 rad の不感帯）。学習も同じゲインとモデルなので、首のゲインを変えるなら学習と実機で一緒に変える。

以前の比べ（首を常に HOME で学習した方策で、首を HMD のように動かすと失敗の区間が増えた：192 対のうち HOME だけ最後まで追えた 17 区間、動かしたときだけ 3 区間）は、首をお手本で動かす新しい学習のモデルでやり直す。

### 頭のロールとピッチを空間に合わせる（オプション）

`MICROBAN_WHOLEBODY_HEAD_ROLL_PITCH=world`（常駐サービスなら `/etc/default/microban-pico-runtime` に書く。シミュレーションは `--wholebody-head-roll-pitch world`）で、頭のロールとピッチを、胴に対してではなく空間に対して、お手本の頭（操縦者の頭）に合わせる。
既定は `body`（今までどおり、お手本の首の角度をそのまま首に入れる）。IK トラッキングの方策のときの首（`hmd_head`）は、もとから IMU で胴の傾きを打ち消して空間に合わせている。

- 首は、お手本の首の角度に加えて、ロボットの胴の傾きのうちお手本の胴の傾きからずれた分を打ち消す（IMU の胴の向きとお手本の胴の向きの、ヨーを除いた差）。胴がお手本どおりなら首は `body` と同じ。ヨー（左右）は今までどおり胴に対して（IMU のヨーは長くは当てにならない）。
- そのずれは 1 秒の時定数でならし、20° までにする。方策は首の角度と速度を観測で見ているので、首をすばやく動かして方策を揺らさないため。歩くときの約 1 Hz の揺れは打ち消さず、しゃがむ・倒れかけて戻る・お手本ほど傾けないといった、ゆっくりしたずれを打ち消す。
- 制限と速さ（`neck_limits_rad_json`、2.5 rad/s）は `body` と同じ。入り・立つ・止めたあとに `hmd_head` が動いていれば、首はこれまでどおり HMD に従う。

シミュレーション（MuJoCo、サーボのモデル、IMU の遅れ、PICO の録画 6 種：歩く・押されながら歩く・ひねって歩く・しゃがむ・押されて立つ・手で作った首の動き。乱数 3〜10 通り）：
胴のお手本からの傾き、胴の回転の速さ、押されたあとの戻り方は `body` と同じで、首と胴が揺れ続けることはなかった（押されたあと胴の揺れは 3 秒で収まり、首は胴のゆっくりした戻りに 1 秒遅れで付いていくだけ。首の目標の 1 Hz を超える成分は 3 mrad 以下）。
IMU の遅れを 6 刻み、ノイズを 0.3° にすると方策そのものが倒れやすくなるが、倒れた数は `body` 20/50、`world` 21〜22/50 で変わらない。
頭の空間での傾きのずれは、首を P900 で動かしたとき、しゃがむ 3.5° → 2.1°、押されて立つ 2.4° → 1.6°、歩く 2.9° → 2.8°。学習と同じ P125 では、サーボのモデルの摩擦（約 0.1 rad の不感帯）のため首が小さな補正にほとんど動かず、差は -0.2〜+0.3°。
時定数を 0.5 秒より短くすると、歩くときに首が揺れに遅れて付き、かえって頭が揺れた（2.8° → 3.2°）。2 秒にすると、押されたあとの戻りに遅れて付き、P125 ではかえってずれた（2.5° → 2.65°）。

## IMU の yaw のずれ（実機で測るまでの案）

**今の作り**：BMI088（加速度とジャイロの 6 軸）を Madgwick（`ahrs`、gain 0.033、200 Hz）で積分している。
地磁気がないので、yaw は加速度で直らない。ジャイロの零点（バイアス）を差し引く処理は、ライブラリにも `ThreadedIMUReader` にもない
（起動時の 50 サンプルは加速度だけで、初期の傾きを作るため）。だから yaw のずれは、ジャイロの鉛直まわりの零点の積分になる。

**見積もり**（BMI088 のデータシート：零点 ±1 °/s（典型）、温度係数 ±0.015 °/s/K、雑音 0.014 °/s/√Hz）

| 条件 | ずれの速さ | 5 分で |
|---|---|---|
| 今のまま（零点を引かない） | 個体の零点そのもの、0.1〜1 °/s | 30〜300° |
| 起動時に静止して零点を引く | 温度の変化の分。胴が 10〜20 K 温まると 0.15〜0.3 °/s | 45〜90°（温まりきるまで） |
| 雑音だけ（ランダムウォーク） | | 約 0.3° |

**全身トラッキングへの効き方**：開始のたびにお手本の yaw を IMU に合わせるので、効くのはその開始からたまった分 δ だけ。
δ がたまると、方策はお手本との向きの差 δ を直そうとして、ロボットを実際に −δ 回す（観測の `ref_anchor_ori_b`、`ref_anchor_lin_vel_b`、`ref_anchor_ang_vel_b` が δ 回る）。
操縦者から見ると、ロボットの向きと歩く向きが δ ずつずれていく。傾き（重力）は加速度で直るので、立つことと姿勢のずれの停止（重力の z）は影響を受けない。

**実機で測ること**：

1. トルク OFF で平らな台に置き、`make imu` の yaw（2 Hz で表示）を 5 分記録する → 零点のずれ（°/分）。
2. 数分動かして胴が温まった直後に、1 をもう一度 → 温度の分。
3. 全身トラッキング中、操縦者が正面を向いたまま 2〜3 分動き、ロボットの向きの変化を床の印かカメラで測る。

**測るまでの扱い**：

1. 開始ごとに合わせる（今の作り）。お手本の向きは、開始からの操縦者の向きの変化だけを使い、ロボットの向きの基準は開始時の IMU の yaw。
   ずれは 1 回の開始の間だけたまる。向きがずれてきたら、PC で止めて開始し直す（RESTART）と 0 に戻る。1 回の開始を数分以内にする。
2. 測ったずれが 1 分で数度を超えるなら、起動直後の静止中（今の加速度の 50 サンプルと同じとき）にジャイロも平均して零点を引く。個体の零点の分が消え、温度の分が残る。
3. それでも足りなければ、IK トラッキングの方策で止まって立っている間（速度の指令 0、関節がほぼ静止）に、ジャイロの z をゆっくり平均して零点を更新する。全身トラッキング中は更新しない。
4. それでも足りなければ、外の基準が要る（地磁気センサーを足す、PC でカメラの映像から向きを推定する）。

## シミュレーションでの試験

```bash
make teleop-sim ALLOW_DRYRUN_POLICY=1          # 実機と同じ動作、操縦は UDP 5555、お手本は UDP 5556
PYTHONPATH=src uv run --with h5py python tools/wholebody_reference_sender.py <motion.h5> \
    --clip picoteleopit_rec06 --start-s 13 --control-port 5555
```

送り手は録画を 50 Hz に補間し、PC と同じ旗で流す（最初の 3 秒は CALIBRATED だけ、そのあと CALIBRATED と ACTIVE、終わると ACTIVE を落とす）。
`--control-port 5555` は、PICO のブリッジの代わりに A と R3（トリガーは離したまま）を送る（頭なしで試すとき）。
R3 で全身の方策が自分のお手本で立ち、ACTIVE が立って操縦者が 0.5 秒止まって立つと合流し、終わると HOME に戻って立つ。
PC の写しと試すときは PC 側の送り手を使う。

## 実機で確かめること

1. Pi Zero 2W での 1 刻みの時間：全身の方策の推論（ONNX、1 スレッド）を含めて 50 Hz に収まるか（ログの `Control timing` の overruns）。
2. お手本の受信：Wi-Fi での包みの間隔、失う率、遅れ。「5 フレーム以上の抜け」「0.1 秒届かない」「遅れ 0.15 秒」で止まりすぎないか。
3. IMU の yaw のずれ（上の測り方）。
4. 開始の直後にロボットが回り出さないこと（yaw 合わせ）。
5. 止める処理：PC で止める、Wi-Fi を切る、PC を落とす → 0.1 秒で惰性に入り、HOME に戻り、全身の方策で立ち続けること。止めたあと、PC で開始し直すまで合流しないこと。
6. 過電流：大きな全身の動き（腕を振る、しゃがむ）での電流の推定（停止の線は 15 A。シミュレーションでは追従中 1〜2.5 A）。
7. 転倒 → 起き上がり → 全身の方策の入り → 立つ。B でトルク OFF。R3 OFF で HOME。R3 で入り直す。
   全身の方策で立っている間に震えないこと（震えたら、戻す手段は `wholebody.onnx` を外すこと：IK トラッキングの方策で立つ）。
8. 首：お手本の首の角度に追従し、カメラの映像で操縦できること。P125 での遅れ（シミュレーションで約 0.5 秒）と止まったときのずれ（約 0.1 rad）。
   `MICROBAN_WHOLEBODY_HEAD_ROLL_PITCH=world` では、ロボットの胴が傾いても（しゃがむ、押されて戻る）カメラの水平がお手本の頭に合うこと、首と胴が揺れ続けないこと。
9. 腕：PICO の右トリガーを押しても、全身の方策の腕が上書きされないこと。首は立っている間 HMD に追従すること。
10. サーボの温度：全身の動きを数分続けたとき。
